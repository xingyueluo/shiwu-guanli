# 答辩演示脚本 & 常见问题（1-2 周课上团队演示用）

## 演示动线（约 6 分钟，每一步都有对应得分点）

1. **打开线上地址 → 注册账号**（30s）
   话术：「前后端完全分离——这个页面是纯静态 SPA，所有数据都走 /api 的 JSON 接口。」
2. **新建 4 个任务，分别放进 4 个象限**（1min）
   演示弹窗里的象限单选；建完立刻在「今日焦点」看到按 ①→②→③→④ 优先级排序。
   得分点：完整性——不是简单 to-do，有优先级模型。
3. **切到四象限视图，把一张卡从「③ 委托办」拖到「② 计划做」**（1min）
   话术：「拖拽用的是 HTML5 Drag&Drop API，放下时只发一个 PUT 请求改 quadrant 字段，
   后端把它拆成 importance/urgency 两个维度存进 SQLite。」
4. **跑番茄钟**（1.5min，可先把时长口头说明为演示加速）
   强调：「计时用结束时间戳做差，不是一秒一秒减——切到别的标签页回来也不会漂移。」
   完成一个番茄 → 侧栏出现记录 → 统计页数字同步变化（数据闭环）。
5. **统计页**（1min）
   话术：「这三张图没有用 Chart.js，是我用 Canvas 2D 手绘的，坐标换算、高分屏适配都自己实现。」
6. **打开 devtools 网络面板回看请求**（30s）
   展示 REST 风格：GET/POST/PUT/DELETE、401 拦截、Bearer token。

## 老师可能问的问题与答案

**Q1：密码怎么存的？能还原吗？**
scrypt + 每个用户独立的 16 字节随机盐，单向不可逆；校验时把输入重新散列后用
timingSafeEqual 比对，防时序攻击。数据库里没有任何明文密码。

**Q2：你的 token 和 JWT 什么关系？**
结构就是 JWT 风格：header.payload.signature，签名用 HMAC-SHA256。
我为了答辩能手写全部逻辑，用 Node 内置 crypto 自己实现了签发/校验，没装 jsonwebtoken。
服务端不存 session，校验签名+过期时间即可，天然支持水平扩展。

**Q3：怎么防止用户 A 看到用户 B 的任务？**
每条 SQL 都带 `user_id = ?` 参数条件（不是拼字符串）；即使 A 猜到 B 的任务 id 去
PUT/DELETE，查不到行就返回 404。冒烟测试第 10 组断言专门验证了未登录 401。

**Q4：四象限为什么不用一个枚举字段而用两个布尔？**
两个维度语义独立（重要性不会因紧急性变化而变化），组合出象限只是展示层的计算；
这样以后加「只看重要」这类筛选不用改表结构。

**Q5：哪里用到了异步？事件循环了解吗？**
Node 端 Express 中间件链、fetch 请求、SQLite 同步调用（node:sqlite 是同步 API，
单文件库毫秒级，避免了回调复杂度——这是有意的取舍，量大可换异步驱动）；
前端全部 async/await，搜索框做了 300ms 防抖。

**Q6：部署架构？**
Docker 镜像 = node:24-slim + 代码；Render 挂载持久磁盘到 /app/data 保存 SQLite；
Nginx 不需要，Express 直接托管静态文件 + API 同域，省掉 CORS 问题。

**Q7：哪些地方用了 AI？（作业鼓励但要能讲清）**
如实回答：AI 辅助生成了初版代码骨架和这份文档，但每一处实现我都逐行核对并能讲解
（比如限流中间件、防抖、时间戳计时），并做了 10 组断言的接口测试保证正确性。
本项目为单人项目，贡献度 100%。
